# CareerLens 前端设计

状态：设计稿；尚无界面、截图或浏览器验证。依据用户提供的 frontend-design skill，先完成设计计划与自评，再写 Vue 代码。

## 1. 产品对象与方向

对象是正在修改开发岗简历的高校学生。主要动作是反复粘贴材料、分析、查看证据、补充真实经历。第一屏直接进入工作台，品牌名 CareerLens 与“简历岗位分析”清楚可见。

风格为安静、紧凑的“证据工作台”。唯一主要视觉重点是“命中项 -> 原文证据”的联动；透明的技能覆盖分服务于核对，不使用英雄式大数字或虚构成功率。

## 2. 设计 token

| Token | 值 | 用途 |
| --- | --- | --- |
| canvas | #F7FAFC | 页面底色，冷白 |
| surface | #FFFFFF | 文本编辑区、必要的浮层 |
| ink | #182B2A | 正文与主要标题 |
| teal | #007F73 | 主操作、命中状态和 focus |
| cobalt | #365FC5 | 原文引用和次级交互 |
| amber | #956000 | 警告、待补充证据，始终搭配文字/图标 |

边界色由 ink 低透明度派生；错误用独立的深红状态色，实施时测对比度。颜色不是唯一状态表达。

字体：拉丁文字优先 IBM Plex Sans（仅在能合法自托管且不引入构建外网依赖时使用），中文采用系统思源黑体/Noto Sans CJK SC/Microsoft YaHei 回退。无可用字体文件时直接使用清晰的系统栈，不虚构已经打包字体。

字号：正文 15–16px、辅助 13px、结果分节 18px、页面标题 24px；不随 viewport 线性放大，不使用负字距。数字采用 tabular-nums 对齐。行高 1.5–1.65，说明文字宽度不超过约 72 个拉丁字符。

间距：4/8/12/16/24/32px；输入边框圆角 6px、菜单/模态 8px，不给所有 section 套卡片或统一阴影。内容左对齐，数字与单位依语义对齐。

## 3. 布局方案

比较过上下向导与并排工作台。分析需要反复对照两份材料，选择桌面并排输入、下方整体结果；手机自然纵向排列，不用多步向导隐藏上下文。

```text
CareerLens  简历岗位分析                       [清空]
----------------------------------------------------
简历文本                       岗位 JD  [选择示例岗位]
[行号 + 多行编辑区]              [多行编辑区]
有效字符计数 / 字段错误           有效字符计数 / 字段错误
----------------------------------------------------
[ ] 使用外部模型（将发送尽力脱敏后的材料）  [分析匹配]
----------------------------------------------------
结果状态 / 实际分析模式 / 旧结果提示 / traceId
技能覆盖分 86/100    已匹配权重 6/7   [评分说明]
----------------------------------------------------
命中技能与 JD 要求              对应简历证据
Java       必需 已命中          R2 原文，点击定位
Spring Boot 必需 已命中          R2 原文，点击定位
Docker     加分 待补充           如何补充真实实践
----------------------------------------------------
[结构化简历] [全部证据]                        [导出 JSON]
```

固定工具条和按钮尺寸，加载 spinner 不改变布局。结果区使用可扫描的要求列表和证据面板；移动端不强塞横向表格，单项展开展示优先级和证据。无结果时只提供“填写两份材料后分析”及“载入虚构示例”，不填假分析图。

## 4. 交互

- 表单是真实 label + textarea，展示限制和字数；错误文本用 aria-describedby 关联。
- “载入虚构示例”明确标记材料为虚构，填充前若已有编辑需防止误覆盖。示例结果也必须真实请求计算。
- 主操作统一叫“分析匹配”；请求期间显示“分析中”并提供取消，禁止重复提交。
- JD 模板不可用时可以手动输入，不阻断分析；选模板后依然能编辑。
- 点击命中项的原文按钮，定位证据行、短暂突出目标，并保持键盘焦点可预测。
- 输入变化后旧结果保留但显示“材料已修改，请重新分析”，禁止将旧分数误当当前结果；请求使用序号/AbortController 防晚到回包覆盖。
- 外部模型选项默认关。开启时在同一位置说明会发送尽力脱敏文本，脱敏不保证完整；服务缺 key 时显示明确 mode/warning。
- JSON 导出由真实结果生成；不把原始输入默认写 localStorage；清空时清掉材料、结果、错误和未完成请求。

## 5. 状态文案

| 状态 | 文案与动作 |
| --- | --- |
| 空输入 | “粘贴简历和岗位要求，查看已有证据与待补充项。” |
| 字数不足 | “简历至少需要 20 个字符。”，定位字段 |
| 提交中 | “正在分析匹配…” + 可取消 |
| rules | “本次使用规则提取，复杂语义请核对原文。” |
| degraded | “模型暂不可用，已使用规则提取。” + 安全原因与重新分析 |
| score.value=null | “未识别到可评分的技能要求，请补充具体技术要求。” |
| 0 命中 | “尚未在简历中找到这些要求的证据。”，不指责没有能力 |
| 超时 | “分析超时，材料已保留。请稍后重试。” + traceId |
| 未知异常 | “暂时无法完成分析。请重试或提供此追踪号。” |
| 旧结果 | “材料已修改，以下是上一次分析结果。” |

错误不只显示浏览器 alert；字段错误、页面错误、降级 warning 各有明确位置。不得对用户显示内部服务名、模型 prompt 或堆栈。

## 6. 图标、动效和图表

操作使用 Lucide Vue 的分析、清空、下载、复制、展开、引用等图标，图标按钮有 tooltip 和 aria-label；主提交保留图标与文字。二元设置用 checkbox，结果视图用 tabs，岗位集合用 select/menu。

技能覆盖只需要一条 0–100 的原生 progress/meter 配合文字；无足够数据时不添加装饰饼图。没有图片相关业务需求，不加入库存人像或营销插画；本产品主要视觉资产是可交互的证据标记与受控图标。

只在点击展开和定位时做短促反馈，不自动播放入场动画；尊重 prefers-reduced-motion。focus-ring 清楚可见，命中/缺口/警告同时用文字与图标区分。

## 7. 设计自评后确定的修改

- 去掉通用“AI 求职助手”营销首屏，第一屏保留可操作材料和明确产品名，符合反复使用的工作台任务。
- 去掉大分数 + 装饰渐变的默认组合，分数和 6/7 权重并列，将判断重点交还证据。
- 去掉重复卡片网格，用编辑区域、要求列表和证据面板表达输入/核对关系。
- 没用奶油色/赤陶或单色暗背景；冷白底、青绿动作、蓝色引用、琥珀警告各有语义。
- 词语从“能力不足”改为“简历中未发现证据”，避免把提及覆盖误说成候选人真实能力。

## 8. 前端验收

至少检查 1440px、1024px、768px、390px 和 320px；长技能名、超长单词和大号系统字体不溢出。键盘可完成填表、模板选择、分析、取消、展开、导出，屏幕阅读器获得状态变更。

Playwright CLI 先 snapshot 侦察真实页面，再截图检查；Python Playwright 运行可重复用户流。必须先等动态页面 networkidle 再选元素。输出写入 ignored `output/playwright/`，合成材料之外不截图上传。实际截图出现后再记录通过，本设计稿不能替代界面 QA。
